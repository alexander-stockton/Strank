# ---------------------------------------------------- STRANK FORMATTING RULES ----------------------------------------------------
#
#   1. Only change RANK NAME #, badge image path, or list items for custom ranks, never header labels.
#   2. Badge images live in data/badges/  (example: badges/unranked.svg).
#   3. After a dash, put the exercise name.
#   4. Anything inside (parentheses) in this file is an optional field.
#   5. If you fill in parentheses in ranks.txt, drop the parentheses.
#   6. If you fill in parentheses in ranks.txt, include every field that was inside them.
#   7. Anything outside parentheses is required.
#   8. Anything inside [brackets] in this file is a number, drop the [] after inserting a value.
#   9. Anything inside {braces} in this file is text, keep the {} after inserting text.
#  10. Lists may have any number of entries (minimum 1, recommended 2-3).
#  11. Keep tab-indentation intact, the parser depends on it.
#  12. To denote having no additional weight, write 0lb (or whatever your unit is) if you still want the weight input field to show up in an active workout.
#  13. To denote having no distance, write 0mi (or whatever your unit is) if you still want the distance input field to show up in an active workout.
#  14. Feel free to add your own weight and weight-units. It won't break the app.
#  15. To show an exercise should do reps and just be done with no repeats, make the set count x1.
#  16. Vertical or straight exercises are denoted with an (I) for pencil-like form. (L) for bent. (T) for arms-straight-out.
#  17. Including form or descriptive elements in parentheses inside ranks.txt before weight or reps adds it to the exercise name.
#  18. Changing this format or its rules does not modify how the parser works at all. These are hard-coded rules.
#
# --------------------------------------------------------------------------------------------------------------------------------
